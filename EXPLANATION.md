# Разбор проекта FdF на Python

Этот файл поможет разобраться в устройстве проекта, архитектуре, формулах изометрии и коде для сдачи и защиты лабораторной работы.

## 1. Что такое FdF

FdF (от фр. *Fil de Fer* — проволочный каркас) — классическая задача компьютерной графики:
1. Дан текстовый файл карты высот `.fdf` (таблица чисел). Номер строки — коорд y, позиция числа в строке — коорд x, а само число — выс z в 3D пространстве.
2. Программа считывает файл, строит сетку и проецирует её на 2D экран в изометрии.
3. Каждое ребро соединяет соседние точки по горизонтали и вертикали.

## 3. Разбор модулей

### 3.1. Исключения: `fdf/exceptions.py`

Собственная иерархия ошибок:
```python
class FdfError(Exception):
    """баз класс ошибок"""

class MapFormatError(FdfError):
    """ошибка формата карты"""
```
Зачем нужно: `MapFormatError` наследуется от `FdfError`. В `main.py` одной строкой `except FdfError as err:` перехватываются любые внутренние ошибки формата, отделяя их от системных `OSError` (когда файл не найден на диске).

### 3.2. Модель: `fdf/model.py`

Базовые структуры данных: `Point` и `Map`.

Класс `Point`:
```python
@dataclass(frozen=True, slots=True)
class Point:
    x: int
    y: int
    z: int
    color: str | None = None
```
- `frozen=True` делает объект неизменяемым (immutable) и позволяет использовать его как ключ в словарях/множествах (автоматически создается `__hash__`).
- `slots=True` оптимизирует память и ускоряет доступ к полям.
- Поле `color` хранит строку цвета в формате `"#RRGGBB"` (напр `"#FF0000"`) либо `None`, если цвет не был задан в файле.

Класс `Map`:
- Хранит ширину `width`, высоту `height` и список точек `points`.
- Метод `at(x, y)` возвращает точку по координатам за $O(1)$.
- Реализует `__iter__` для обхода точек циклом `for point in grid:`.
- Метод `neighbors(point)` возвращает соседей справа и снизу:
  ```python
  def neighbors(self, point: Point) -> list[Point]:
      res: list[Point] = []
      if point.x + 1 < self.width:
          res.append(self.at(point.x + 1, point.y))
      if point.y + 1 < self.height:
          res.append(self.at(point.x, point.y + 1))
      return res
  ```
  **Почему только справа и снизу:** требование ТЗ — каждое ребро строится ровно один раз. Если брать всех 4 соседей, линия между точками рисовалась бы дважды (сначала $A \to B$, затем $B \to A$). Беря только соседей справа и снизу, каждое ребро рисуется строго однократно.

### 3.3. Парсер: `fdf/parser.py`

Функция `parse_map(file_path)` читает и валидирует файл:
1. Открывает файл в UTF-8.
2. Пропускает пустые строки в конце файла (по ТЗ: пустые строки в конце файла игнорируются).
3. Если файл пустой — возбуждает `MapFormatError("пустой файл")`.
4. Для каждой строки:
   - Разбивает строку на токены по пробелам: `line.split()`.
   - Проверяет длину: все строки должны быть одной длины. Если длина отличается от первой строки — ошибка `MapFormatError` с указанием номера строки.
   - Для каждого токена вызывается `parse_token`:
     - Высота и цвет могут разделяться запятой: напр `20,0xFF0000` или просто `20`.
     - Проверяет, что z — целое число (`int(parts[0])`). Если нет — ошибка с номером строки и колонки: `строка X, колонка Y: 'значение' — не целое число`.
     - Если указан цвет, проверяет префикс `0x`. Ведущие нули могут опускаться (напр `0xFF` эквивалентно `0x0000FF`). Приводит к виду `"#RRGGBB"` в верхнем регистре.

### 3.4. Проекция и камера: `fdf/projection.py`

Формулы изометрии из ТЗ:
- $x' = (x - y) \cdot \cos(30^\circ)$
- $y' = (x + y) \cdot \sin(30^\circ) - z \cdot z_{scale}$
- $X = x' \cdot scale + offset_x$
- $Y = y' \cdot scale + offset_y$

**Почему выс z вычитается:** в экранных коорд ось Y направлена сверху вниз (0 в левом верхнем углу). Чтобы положительная высота z поднимала точку вверх, экранную координату Y нужно уменьшать (вычитать z).

Автоподгонка под окно (`Camera.fit(grid, width, height)`):
1. Проецирует точки с $scale = 1$ и $offset = (0, 0)$.
2. Находит границы модели: `min_x, max_x, min_y, max_y`.
3. Считает размер: $bbox\_w = max\_x - min\_x$, $bbox\_h = max\_y - min\_y$.
4. Масштаб с отступом 10%: $scale = \min(width / bbox\_w, height / bbox\_h) \cdot 0.9$.
5. Смещение $offset_x, offset_y$ совмещает геометрический центр модели с центром окна.

Бонусы:
- `zoom_at(factor, cx, cy)`: зум с фиксацией точки под курсором мыши (фокус не улетает).
- `height_color(z, z_min, z_max)` и `lerp_color`: расчет цвета по градиенту высот (синий $\to$ зеленый $\to$ желтый $\to$ красный).
- `isometric = False`: параллельная проекция (вид сверху).

### 3.5. Графический интерфейс: `fdf/app.py`

Интерфейс на стандартной библиотеке `tkinter`:
- Не требует внешних зависимостей.
- `tk.Canvas` для векторной отрисовки линий методом `create_line(...)`.
- Обработчик `<Configure>` перерисовывает каркас при ресайзе окна.
- Интерактивное управление:
  - Колесо мыши и `+` / `-` — зум.
  - ЛКМ drag и стрелки — сдвиг модели.
  - `Q` / `E` — поворот угла.
  - `PgUp` / `PgDn` — масштаб высоты z.
  - `P` или `Пробел` — переключение проекции (изометрия / вид сверху).
  - `C` — вкл/выкл градиент высот.
  - `R` — сброс вида.
  - `Esc` — выход.

### 3.6. Точка входа: `main.py`

- Проверяет `len(sys.argv)`. Если не 2 — выводит справку в `stderr` и завершается с кодом 2 (стандарт POSIX для ошибок вызова).
- Загружает карту через `parse_map`:
  - `OSError` (файл не найден / нет доступа) — вывод сообщения в `stderr` и код 1.
  - `FdfError` (ошибка формата карты) — вывод сообщения в `stderr` и код 1.
  - Никаких необработанных исключений и traceback наружу не выходит (строгое требование ТЗ).
- Запускает `App(grid).run()`.

## 5. Частые вопросы на защите

В: Почему `Point` сделан как `frozen dataclass`?
О: Коорд точки и цвет неизменяемы во время работы программы. `frozen=True` делает объект неизменяемым и создает `__hash__`, а `slots=True` экономит память без словаря `__dict__`.

В: Почему `neighbors()` возвращает только соседей справа и снизу?
О: Чтобы каждое ребро строилось ровно один раз. Если брать всех 4 соседей, каждое ребро нарисуется дважды ($A \to B$ и $B \to A$).

В: Почему в формуле проекции выс z вычитается?
О: В экранных коорд ось Y направлена вниз. Чтобы положительная высота шла вверх, экранную коорд Y нужно уменьшать.

В: Почему `tkinter` импортируется только в `app.py`?
О: Разделение логики и интерфейса. Модель, парсер и проекция не зависят от UI и легко тестируются в консоли без открытия окон.
